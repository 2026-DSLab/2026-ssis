# 법령·행정규칙 개정 알림 시스템

감시 대상으로 등록한 법령·행정규칙 **102건**의 개정 여부를 매주 자동으로 확인하고,
무엇이 **몇 조 몇 항에서** 바뀌었는지 정리해 웹 화면과 한글(HWPX) 보고서로 제공합니다.

담당자가 국가법령정보센터에서 법령을 하나씩 검색해 대조하던 일을, 시스템이 대신
확인하고 담당자는 정리된 결과를 검토하는 방식으로 바꾸는 것이 목적입니다.

- 개발: 국민대학교 법인사이트 | 협업: 한국사회보장정보원 정보분석부
- 자료 출처: 국가법령정보센터 Open API

---

## 무엇을 할 수 있나요

브라우저에서 `http://서버주소:5000` 으로 접속하면 네 가지를 쓸 수 있습니다.
별도 프로그램을 설치할 필요가 없습니다.

### 1. 개정 요약

이번 주에 개정된 법령을 법령별 개요와 조문별 변경 내용으로 정리해 보여줍니다.
**최근 5일 · 2주 · 1개월** 중 기간을 골라 그 자리에서 다시 확인할 수도 있습니다.
각 법령은 법제처 원문으로 연결됩니다.

### 2. 전문 비교

감시 대상 102건의 전문을 조문 단위로 열어 봅니다. 개정된 법령은 **개정 전과 후가
나란히** 놓이고 바뀐 부분이 색으로 구분되며, 그 이전 개정까지 거슬러 볼 수 있습니다.

### 3. 문서 인용 확인

작성해 둔 PDF·한글 문서를 올리면, 그 문서가 인용한 감시 대상 법령을 찾아
**인용 횟수와 쪽수**를 보여줍니다. 최근 90일 안에 시행된 개정이 있으면 표시가 붙습니다.
올린 문서는 저장하지 않습니다 — 처리하는 동안에만 메모리에 두고 끝나면 사라집니다.

### 4. 보고서 내려받기

화면에서 본 내용을 기관 양식의 한글(HWPX) 보고서로 내려받습니다.
법령별 개정 내용에 **조문 · 위치 · 구분 · 변경 내용** 네 칸짜리 표가 붙어 있어,
표만 확인해도 개정 내용을 파악할 수 있습니다.

## 처음 설치하기

### 준비물

| | |
|---|---|
| Python | 3.11 이상 |
| PostgreSQL | 14 이상 |
| 국가법령정보 Open API 인증키 | <https://open.law.go.kr> 에서 발급 |
| LLM API 키 | 요약 기능을 쓸 경우 |

### 1단계 — 설치

압축을 푼 폴더에서 실행합니다.

```bash
pip install -e ".[openai,web,dev]"
```

제대로 설치됐는지 확인합니다. **455건이 모두 통과하면 정상입니다.**

```bash
python -m pytest -q
```

### 2단계 — 환경 설정

`.env.example` 파일을 `.env` 로 복사한 뒤 값을 채웁니다.

```bash
copy .env.example .env
```

| 항목 | 설명 |
|---|---|
| `LAW_API_OC` | 국가법령정보 Open API 인증키 |
| `POSTGRES_HOST` / `POSTGRES_PORT` | 기본값 `127.0.0.1` / `5432` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` | PostgreSQL 계정 |
| `POSTGRES_DATABASE` | 기본값 `law_tracking_db` |
| `OPENAI_API_KEY` | 요약에 쓰는 LLM 키 |
| `SUMMARY_MODEL` | 쓰는 모델 이름 |

> **`.env` 에는 비밀번호와 인증키가 평문으로 들어갑니다.** 파일 권한을 최소로 두시고,
> 다른 곳으로 복사하거나 메일로 보내지 마십시오.

원내 모델(Qwen 등)로 바꾸실 때는 `SUMMARY_PROVIDER` · `SUMMARY_MODEL` 두 줄과
해당 키만 바꾸면 됩니다. 나머지 코드는 고치지 않아도 됩니다.

### 3단계 — 데이터베이스 구축

```bash
python scripts/setup_db.py
```

데이터베이스 생성 → 표 만들기 → 감시 대상 102건 등록까지 한 번에 끝납니다.
**여러 번 실행해도 기존 자료를 지우지 않습니다.**

| 옵션 | 하는 일 |
|---|---|
| (없음) | 전체 구축 |
| `--check` | 아무것도 바꾸지 않고 현재 상태만 확인 |
| `--skip-watchlist` | 표만 만들고 감시 대상 등록은 건너뜀 |

### 4단계 — 첫 자료 수집

처음에는 감시 대상 전체의 현재 전문을 받아 와야 합니다. 몇 분 걸립니다.

```bash
python scripts/run_weekly.py
```

이어서 요약까지 만들려면 `--full` 을 붙입니다. **이 단계에서 LLM 호출 비용이
발생합니다** — 붙이지 않으면 감지·비교만 하고 비용은 들지 않습니다.

```bash
python scripts/run_weekly.py --full
```

### 5단계 — 웹 서버 켜기

```bash
python -m webapp.app
```

브라우저에서 <http://127.0.0.1:5000> 으로 접속합니다.

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `WEB_HOST` | `127.0.0.1` | 같은 PC에서만 열립니다. 다른 자리에서 접속하려면 `0.0.0.0` |
| `WEB_PORT` | `5000` | 포트 번호 |
| `WEB_DEBUG` | 꺼짐 | **원내에 올린 상태에서 켜지 마십시오.** 브라우저에서 서버 명령을 실행할 수 있게 됩니다 |

## 매주 자동으로 실행하기

Windows 작업 스케줄러에 등록하면 담당자가 조작하지 않아도 매주 실행됩니다.

```powershell
# 1) 등록해도 돌아갈 환경인지 먼저 점검 (아무것도 바꾸지 않습니다)
powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1 -Verify

# 2) 매주 월요일 06:00 등록
powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1

# 요일·시각을 바꾸려면
powershell -ExecutionPolicy Bypass -File scripts\register_task.ps1 -DayOfWeek Friday -Time 18:30
```

실행 기록은 `out/logs/` 에 쌓입니다.

## 데이터베이스 구성

표 5개를 씁니다. **`documents` 의 전문이 모든 자료의 출발점이고**, 나머지는
거기서 만들어지거나 처리 과정을 기록한 것입니다.

| 표 | 담는 것 | 대략 |
|---|---|---|
| `documents` | 법령·행정규칙 **전문** — 법제처가 준 원본 그대로 | 203행 |
| `watchlist` | **감시 대상 목록** — 법령 이름·ID·마지막으로 확인한 일련번호 | 102행 |
| `change_log` | **개정 이벤트** — 어느 법이 언제 몇 번에서 몇 번으로 바뀌었는지 | 1,911행 |
| `article_diff` | **조문 단위 변경** — 몇 조 몇 항이 어떻게 바뀌었는지 | 1,094행 |
| `law_summary` | **요약 결과** — 웹 화면이 읽는 유일한 표 | 78행 |

### 알아 두실 점

**이전 버전을 지우지 않습니다.** 개정이 확인되면 새 전문을 추가할 뿐이라,
개정 전·후 비교와 지난 개정 추적이 가능합니다.

**`documents` 와 `article_diff` 는 비운 채로 시작해야 합니다.** 이 두 표에 행이
있는지 없는지가 "이 버전을 이미 처리했는가"를 판단하는 신호입니다. 미리 채워 넣으면
그 항목은 영원히 "처리됨"으로 잘못 판단되어 개정을 감지하지 못합니다.
최초 수집은 반드시 위 4단계(`run_weekly.py`)로 하십시오.

**감시 대상을 늘리려면** `scripts/load_watchlist.py` 의 목록에 추가하고 다시
실행하면 됩니다. 처리 절차는 고치지 않아도 됩니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| `환경변수 ... 가 설정되지 않았습니다` | `.env` 파일이 있는지, 값이 비어 있지 않은지 |
| `PostgreSQL 연결 실패` | PostgreSQL이 켜져 있는지, 계정·비밀번호가 맞는지. `python scripts/setup_db.py --check` 로 확인 |
| 웹 화면이 비어 있음 | 아직 수집·요약을 돌리지 않은 상태입니다. `run_weekly.py --full` 실행 |
| 첫 화면 날짜가 오래됨 | 마지막으로 배치를 돌린 날짜입니다. 자동 실행이 등록돼 있는지 확인 |
| 법령 조회가 실패함 | 국가법령정보 API 쪽 일시 장애일 수 있습니다. `out/logs/` 의 기록을 확인하고 잠시 뒤 재실행 |

법령 1건만 따로 자세히 확인하고 싶을 때는 이렇게 씁니다.

```bash
python scripts/run_single_check.py 009199     # 전자정부법
```

문서 1개의 인용 법령만 명령줄에서 확인할 때는 이렇게 씁니다.

```bash
python scripts/check_document.py 문서.pdf
```
